# Tungstate Build Syllabus

Extracted from `DESIGN.md` §11. Each slice gets its own brief under `docs/slices/`.

## 11. Build order

Each slice is small enough to finish in days, ends in something runnable, and teaches one or two Rust concepts. **DECIDED: drain first.** The user is new to Rust, so slices 0–9 are entirely synchronous; `tokio` first appears in slice 10.

### How a slice runs (changed 2026-09-09)

Originally the user wrote the code and Claude reviewed. Writing Rust as a newcomer proved to be the slow step, and the user is shipping a product, so that step moved to Claude. Everything the user is fast at stayed with them.

1. Claude writes a **slice brief**: goal, runnable outcome, the design decisions and their alternatives, acceptance criteria, and the tests that must pass. The brief is the spec.
2. Claude implements it, and does not stop until `build`, `test`, `clippy -D warnings`, `fmt --check` and CI on all three platforms are green.
3. Claude writes a **tour** at `docs/slices/NN-tour.md` walking the shipped code and explaining each Rust concept where it appears. Source comments stay short and load-bearing; the teaching lives in the tour.
4. The user reads the tour and the diff, then says go. Claude stops after every slice.

Claude still asks before choosing on anything non-obvious. No silent design calls.

The "Teaches" column below is adjusted for a Rust newcomer: ownership and borrowing in slice 1, `Result` and error design in slice 1–2, traits and trait objects in slice 1, enums as state machines in slice 3, threads and channels in slice 3–4, lifetimes when the parser needs them in slice 5.

**DECIDED (NAS is reached via Finder mount and via FTP):** the first drain (slice 3) targets the Finder-mounted volume through the local backend with network-mount detection. Slice **4b** then widens the seam — a link end becomes a connection plus a path inside it — and **4c** adds FTP itself, with `Capabilities` flags for FTP (no native checksum, non-atomic rename on some servers) and the same drain over `ftp://`. **4e** puts connections in the desktop app. Slice 12 then shrinks to WebDAV and S3, since FTP landed in 4c and SFTP is hand-rolled (DESIGN.md §6). FTP has no server-side checksum, so `readback` is the recommended (not default) verify level for FTP links, and the CLI says so when such a link is created.

Slices 0–4g are "v0.1: the drain works and I trust it, over a mount and over FTP." Slices 5–9 are "v0.2: governance." 10–14 are "v0.3: daemon and UIs."

**Licence and hosting (DECIDED):** `MIT OR Apache-2.0`, public GitHub repository, Rust ecosystem convention.



## Scope changes made during the build

- **A rolling `main` build, so there is always something installable (2026-09-12).** Releases were tag-only, which meant testing the app as built meant either cutting a version or building it locally — and the local `tauri build` is the one that does not work. `release.yml` gained a `workflow_run` trigger on CI, so every commit that goes green on `main` refreshes a `main` prerelease carrying the same artefacts a real release does. Gated on CI rather than on the push, because a build that compiles and fails its tests is exactly the build nobody should install; and it checks out the commit CI *tested* rather than the current head, because another merge can land between the two runs. It reuses `release.yml` instead of getting its own workflow so that what you test from `main` is built the same way as what you release. The publish job also gained a completeness check: the desktop artefact upload has to use `if-no-files-found: warn` (its paths list every platform's bundle and only one matches per runner), so a stale bundle path would empty the desktop half of a release in silence — now it fails the publish instead.

- **The narrowing tests measured the scheduler, not the governor (2026-09-12).** Slice 4g's ramp-down tests slept for a real 40ms window and let the wall clock answer. `sleep` may overshoot by any amount; an overshoot collapses the measured rate below the 95% keep-ratio; and one collapsed window sets `Trend::Settled`, which is permanent by design — so narrowing stalled and never resumed. It failed on macOS CI as `left: 3, right: 1`. `Governor` gained a `reconsider_after(moved, elapsed)` seam alongside `reconsider`, so the tests supply the duration instead of sleeping through it; the production path still reads the clock, and `nothing_is_decided_before_a_full_window_has_passed` still exercises it. The tests are now deterministic (150/150 under CPU load, where they had been failing intermittently) and instant. The principle restated: a test that sleeps is a test that asserts on the machine it happens to run on.

- **`quarantined` read the wrong filesystem (2026-09-12).** The desktop app's `quarantined` command built `link.destination.path.join(".tungstate-quarantine")` and walked it with `std::fs`. For a remote link `destination.path` is a *connection-relative* path, so that resolved against this machine's working directory, found nothing, and returned an empty list — "nothing is set aside" however many files were. The read now lives in `tungstate-transfer` next to the code that writes quarantine, takes the destination backend, and reuses the existing `walk::files_under`. It also asks by listing rather than by `stat`, so "nothing is set aside" and "the destination cannot be reached" stay different answers; an unreachable NAS is an error, not an empty list. Latent rather than live — the command is registered but no screen calls it yet — and deferred out of 4d and 4e before being fixed here.

- **Slice 4e grew `connection update` and `connection password` (2026-09-12).** The window gained an edit dialog, and the CLI is the reference surface — it must not be able to do less than the window, or the two disagree about what a connection can be. `password` turned out to be a missing recovery path rather than a convenience: `BackendError::Auth` tells you to re-enter the password, and until now there was no way to, because `connection remove` is refused while any link points at the connection. The journal API that backs both encodes the one thing that is *not* editable — `ConnectionSettings` has no `name`, because the name is the link-spec token and the keychain account, so a rename is two migrations wearing one hat.
- **The flaky FTP CI job fixed inside slice 4e (2026-09-12).** Not a regression: green on `slice-4d`, red on `slice-4f`, green on `slice-04-concurrency`, red on `main`, with no code change to explain any of it. The image creates the FTP account before its home directory, and the workflow repaired that in a step *after* a readiness poll that only checked login — but a login can succeed in the window before the root is listable. Fixed at the root twice over: a bind-mounted host directory makes the home exist before the container does (so the repair step is deleted rather than tuned), and the poll now LISTs the root over a passive data connection, which is what the suite's first call does. The push trigger also gained `fix-**`, because slice 4g shipped on such a branch and so never got a three-platform run at all.
- **The endpoint helpers moved from the CLI into the journal (slice 4e).** `describe` and `place` were byte-identical in `cli/src/ends.rs` and `gui/src/main.rs`, and 4e would have added a third copy. They moved with `parse_end`, `connection_prefix` and `EndError` to `tungstate-journal`, which owns `Endpoint` and `Connection` and which `parse_end` already needed a handle to — so the move cost the journal no new dependency. Two helpers joined them for what the window needs and the CLI never did: `join_display` and `parent_display`, because `Path::join` yields `nas:inbox\a.mp4` on Windows and `Path::parent` on `nas:inbox` answers `Some("nas:")` where the honest answer at a connection's root is `None`.

- **Per-file resume rather than byte-offset, in slice 3.** Everything committed is kept and only the file in flight is redone. Byte-offset resume moves to slice 4c or later, where FTP makes partial transfers genuinely expensive; over a mounted volume the code to track and validate partial writes carries more corruption risk than the minutes it saves.
- **Slice 4f inserted (2026-09-11).** Found by using 4d rather than testing it. A link recorded its two roots and not which files the user picked, so a selection lived only in a worker thread and died with the process. Three symptoms, one cause: an interrupted batch could only report the one file that had started, a resumed run re-walked the whole source folder instead of the batch, and no queue could be shown because none existed outside a running process. Migration v5 stores the selection; "no rows" keeps meaning the whole root, so saved folder-pairs and every existing link are unchanged. "Progress events" moves out of slice 4 into here, leaving slice 4 as concurrency, bandwidth caps and reachability pausing.
- **Slice 4d inserted, connections moved to 4e (2026-09-11).** Unplanned, and found by using the desktop app rather than by testing it. A one-off browser transfer makes an unsaved link, `links()` hides unsaved links, and recovery is scoped per link — so an interrupted browser transfer was unreachable and its partial orphaned on the destination for ever. Two other bugs in the same session: Tauri resolved an empty ACL so the window could not hear any engine event, and the Activity view used five class names the stylesheet does not define. The lesson recorded: "compiles and launches" is not a done bar for anything with a screen.
- **Slice 4b split into three (2026-09-11).** What was one "OpenDAL FTP backend" slice became the seam (4b), FTP (4c), and the desktop app's connection screens (4d). The seam is the part that touches every crate and needs a schema migration, and it can be proven on all three CI platforms with no network at all by running the existing transfer suite through OpenDAL's own `fs` service. Shipping it first makes FTP a service registration plus its quirks rather than a rewrite.
- **SFTP leaves OpenDAL (2026-09-11).** OpenDAL's SFTP service is Unix-only, refuses password authentication, and delegates host-key checking to the system `ssh` client — contradicting three-platform support, password auth for a consumer NAS, and tungstate-controlled trust-on-first-use. It will be hand-rolled on `russh` + `russh-sftp` behind the same `Backend` trait. Recorded in DESIGN.md §6; implemented much later.
- **The engine gained a commit path that does not rename (slice 4c).** `Capabilities::atomic_rename` was defined in slice 1 and read by nothing until FTP, whose OpenDAL service answers `rename` with `Unsupported`. Without rename the only route to the final name is to write to it, so `copy_verify_commit` branches and recovery follows. `ConflictAction::Replace` is refused on such a destination, because moving the existing file aside is the promise it cannot keep. S3 and WebDAV need the same path in slice 12.
- **An old binary can no longer open a newer journal (2026-09-11).** Schema v4 makes a link end relative to a connection, so a build that does not know about connections would read a remote path as a local one. `migrate` returns `JournalError::TooNew` rather than skipping. Recorded in DESIGN.md §4c.
- **Links are stored in the journal database, not a config file.** A link's definition and its progress then update together, and a resumed drain finds its own interrupted work by link id. This widens the journal crate from provenance to persistent state.
- **Network-mount detection moved out of slice 1 into slice 4.** Reading `MNT_LOCAL` on macOS or `GetDriveType` on Windows means either `unsafe` FFI, which the workspace lints forbid, or a heavy dependency. It is also a poor second lesson in Rust. Nothing needs it until slice 4 picks a default verification level per link. Slice 1 instead discovers hard-link and case-sensitivity support by probing the filesystem, which is safe, portable, and more accurate than asking the operating system.
